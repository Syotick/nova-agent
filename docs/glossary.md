## ① 协议与标准

| 术语 | 大白话 |
|---|---|
| **MCP（Model Context Protocol）** | 让 AI 工具"即插即用"的开放协议（AI 界的 USB-C）。约定了 server 和 client 怎么说话 |
| **MCP server** | 工具的**提供方**，是一个独立进程（任意语言），通过标准输入输出（stdio）对话。例：filesystem、playwright |
| **MCP client** | 工具的**连接方**（本项目就是）。负责拉起 server 进程、握手、拿工具清单、调用工具 |
| **统一工具注册表（ToolRegistry）** | 内置工具 + MCP 工具走同一条装配管道（`server/toolRegistry.ts`）。内置定义 `{id,description,inputSchema,createExecute(runtime)}`，MCP 用同一套 record/事件/修剪包装——可插拔、可分配、主循环只留一行装配 |
| **stdio（标准输入/输出）** | 进程与外界交换数据的默认通道。MCP server 的"程序入口"就是一行行 json 从 stdin 进、从 stdout 出——不用开端口 |
| **Agent Skills（技能）** | 给 agent 的"操作手册"（SKILL.md），Claude Code / Cursor 等多家用的事实标准 |
| **SKILL.md** | 技能的文件格式。一个文件夹一个技能：frontmatter（身份证）+ 正文（操作手册） |
| **frontmatter** | 文件最顶部 `---` 包住的键值元数据（name / description / when_to_use） |
| **when_to_use** | frontmatter 里的字段：告诉模型"这技能什么时候该用" |
| **AGENTS.md** | 开放的项目记忆文件约定（OpenAI/GitHub 推进）："给 agent 看的项目说明"，Claude Code / Codex 等多家都读 |
| **AGENTS.local.md** | AGENTS.md 的私有版：只在本机生效，不入库（.gitignore 排除） |
| **[DONE] 协议** | 收敛的机器可判信号：只有回复以 [DONE] 开头才认为任务完成（配合"验证通过才允许"的约束） |

## ② Agent 核心概念

| 术语 | 大白话 |
|---|---|
| **Agent** | 会"自己决定下一步做什么"的 AI 程序，不是一问一答的聊天机器人 |
| **Agent Loop（agent 循环）** | 让模型反复"思考 → 行动 → 看结果 → 再思考"的循环。核心循环由框架（AI SDK）做，我们做外围装配 |
| **turn（回合）** | 用户发一条消息 → agent 完整处理一次（内部可能调多次工具）→ 给出最终回答。多轮对话 = 多个 turn |
| **token（分词）** | 模型读写文本的基本单位（约 1 个英文单词≈1-2，1 个汉字≈1-2）。计费与上下文窗口都按它 |
| **工具调用循环（tool-calling loop）** | 模型说"我要调 xxx，参数是…"→ 程序执行 → 结果喂回 → 模型再决定下一步。agent 干活就靠它 |
| **subagent（子 agent）** | 主 agent 派出去独立干活的"小 agent"，干完把结果带回来 |
| **嵌套深度** | 子 agent 又派子 agent 的层数。本项目最多 3 层（防成本爆炸） |
| **中断传播** | 主回合被"停止"时把中断信号向下传递：一起停子任务、杀未跑完的命令进程 |
| **系统提示词（system prompt）** | 每次对话开始给模型的"总纲"：你是谁、怎么干活、有哪些工具和限制 |
| **persona（人设）** | system prompt 最开头那句"你是……"，agent 身份设定 |
| **prompt 工程** | "怎么写提示词让模型更好用"的工程实践：给约束、给策略、给例子 |
| **SSE（Server-Sent Events）** | 服务器向浏览器"单向实时推送"的协议。用来一帧帧推 agent 的过程事件（流式打字机、实时工具卡片） |
| **streamText** | AI SDK 的一个函数：发起一次"带工具"的模型对话流，内部做多步工具循环 |
| **generateText** | AI SDK 的一次性生成（不流式）：要一段文字就用它（如压缩摘要） |
| **编排层驱动（orchestrator-driven）** | 循环是**外面的代码**在驱动，不是模型自己"自觉继续"。模型一个 turn 结束≠任务结束 |
| **Vibe coding** | 用自然语言描述目标，让 AI 自己写代码、跑、看错、改、直到成功。目标驱动而非逐句问答 |
| **指令驱动 vs 目标驱动** | 指令驱动＝你说一句它答一句；目标驱动＝你给目标它自己连续干到底 |
| **收敛（converge）** | 任务做到"明确完成"的状态，以 [DONE] 协议判定 |
| **自愈循环（self-healing loop）** | 上轮结果（含失败输出）拼进下轮 → 模型分析错误、修复、重验——"错→改→再验"闭环 |
| **上下文压缩** | 对话太长时，让模型把较早历史总结成摘要，省 token、防溢出 |
| **跨会话记忆** | 存在"对话历史之外"的长期事实（个人偏好、项目约定），跨会话有效 |

## ③ 工程与进程

| 术语 | 大白话 |
|---|---|
| **spawn（派生）** | Node 里启动一个新进程的 API（相当于命令行开了个新程序） |
| **子进程（child process）** | 由我们程序启动的另一个程序 |
| **进程树（process tree）** | 命令会再拉起子命令（npm → node → …），形成父→子→孙的树。**杀进程要连树根一起杀** |
| **detached（脱离）** | spawn 选项：让子进程成为独立"进程组组长"，之后能对整个组发信号（unix 杀树用） |
| **SIGTERM / SIGKILL** | 两种终止信号：温和（让程序收拾完再退）/ 强杀（拦不住）。杀树先温和后强杀 |
| **taskkill** | Windows 杀进程命令。`/T`=连子进程树，`/F`=强制 |
| **stdout / stderr** | 进程的两个输出通道：正常结果 / 报错信息。两个都要收 |
| **exit code（退出码）** | 进程结束的数字：0=成功，非 0=失败 |
| **windowsVerbatimArguments** | Node spawn 的 Windows 开关：参数"原样"传给 shell。不开会被引号坑 |
| **幽灵进程（zombie/orphan）** | 中断后没被杀干净、还在后台跑的进程（占端口、耗资源） |
| **会话进程注册表** | 会话 id → 该会话正在跑的进程集合的账本，中断时据此清理 |
| **超时（timeout）** | 一条命令/调用最多等多久，超了强制终止（防无限挂起） |
| **连接池（connections）** | 一个 Map：server id → 活跃连接。复用连接，不重复起进程 |
| **配置热加载** | 改配置后不用重启程序就生效（MCP 配置存 json + 管理页 CRUD） |
| **健康检查（health check）** | 定期问"你还好吗"，坏了标记断开并安排重连 |
| **指数退避（exponential backoff）** | 重试等待时间翻倍（5s→10s→20s…封顶），防重试风暴 |
| **Promise.race** | 让多个异步"赛跑"，谁先出结果算谁的。常用来做超时 |
| **轮摘要签名（round signature）** | 取每轮输出末尾若干字符算哈希，比较"两轮是否相同"（熔断用） |
| **熔断（circuit breaker）** | 连续几轮输出一模一样＝疑似卡死 → 提前止损，不烧完轮数 |
| **预算（budget）** | 轮数上限 + 时长上限 + 每轮步骤上限（三重/四重保险），防失控烧钱 |
| **resume（续跑）** | 每轮消息都落库；中断后再发一次，从历史接着跑（文件即状态） |

## ④ 数据与算法

| 术语 | 大白话 |
|---|---|
| **SQLite / 持久化** | 把会话/消息/记忆存进本地文件数据库（Node 内置 node:sqlite），重启不丢 |
| **LRU（Least Recently Used）** | 缓存淘汰策略：满了优先删"最久没用过的"。记忆库用了它 |
| **去重合并（dedup+merge）** | 写新记忆时若与旧记忆高度相似，更新旧条而非新增 |
| **相似度 / Jaccard** | 衡量两段文字多像。经典 Jaccard＝交集/并集 |
| **bigram（2-gram）** | 切成"相邻两字"的片段集合（中文常用，一个词常由两个字构成） |
| **短侧覆盖率** | 交集 ÷ 较小那侧的片段数。判断"A 是不是 B 的补充/改写" |
| **Top-K** | 只取排名前 K 个结果（这里是相关度最高的前 5 条记忆） |
| **词面检索** | 按"字符串包含"匹配（穷人的相似度）。比语义检索粗糙但零依赖、可解释 |
| **Embedding / 向量库** | 把文字转成向量、按"语义远近"匹配的现代做法（本文件刻意不用） |
| **FTS（全文检索）** | 数据库的全文索引（中文要分词器，也刻意不用） |
| **touch（保活）** | 记忆被用上时刷新"最近使用时间"——LRU 淘汰时不会被先删 |
| **热度（时间衰减）** | 记忆排序里的"最近使用"权重：`recencyFactor` 按 `last_used_at` 90 天线性衰减，越近越高 |
| **覆盖率（检索）** | 命中片段占记忆内容的比例：检索综合分的一部分（0.7 权重），防"长记忆命中一个词就虚高" |
| **存量归并（consolidate）** | 定期对整个记忆库扫一遍，把历史积压的高相似条目合并 |
| **节流（throttle）** | 高成本操作不每次都做，隔一段时间才做一次（如 5 分钟最多归并一次） |
| **一键可插拔（可配置开关）** | 某能力用一个开关整体启用/停用。如记忆＝Agent"内置工具"里的"记忆"勾选，同时管 remember 工具＋注入＋指令段 |
| **解耦（decouple）** | 把"做什么"和"怎么实现"分开：主循环只调开关/接口，实现细节收在模块内，改一处不牵动全局 |
| **上下文窗口（context window）** | 模型一次能"看见"的最大 token 数。超了会被截断或报错 |
| **上下文占用（context usage）** | 当前这一轮发给模型的总 token 数，接近窗口上限就该压缩 |
| **真实计数 vs 估算** | 真实计数＝API 返回的实际 token（准）；估算＝按字符猜（免费）。能用真实的不估 |
| **摘要（summary）** | 压缩的产物：一段保留"目标/关键事实/完成/待办"的浓缩文本 |
| **阈值（threshold）** | 触发压缩/合并的门槛（如占用超 90%、相似度 ≥ 0.6） |
| **兜底（fallback）** | 主方案没戏时的保底（如"消息数 40 条"是 token 感知之外的保守兜底） |
| **保留比例（retain ratio）** | 压缩后保留多少"原文尾巴"：默认窗口的 16%（token 预算），超预算把最旧保留消息并入压缩，但至少留 5 条 |
| **修剪（prune）** | 超大工具输出喂给模型前裁成"头 + 中间省略标记 + 尾"（默认 8192 → 4096 + 1024），按 Unicode 码点切不拆 emoji；展示/日志仍保留完整输出 |
| **溢出恢复（overflow recovery）** | 模型报"上下文超出"时：先强制压缩旧历史（保留更少）→ 重试这次请求一次，而不是直接失败 |
| **代理对（surrogate pair）** | emoji 等字符在 UTF-16 里占 2 个单元（`'😀'.length===2`）；按码点切（`Array.from`）才不会从中间劈开 |

## ⑤ 安全与边界

| 术语 | 大白话 |
|---|---|
| **工作区（workspace）** | Agent 的文件"领地"。读写文件、跑命令、收附件都只能在这里 |
| **权限边界（permission boundary）** | 明确"能碰什么、不能碰什么"的那条线，工作区就是它的物理实现 |
| **挂载根（mount root）** | filesystem MCP server 只"看得见"的目录（启动时把目录当根） |
| **项目根（project root）** | 项目代码所在目录（有 package.json 那层）。**默认禁止**当工作区 |
| **路径穿越（path traversal）** | 往路径里塞 `..`/`/` 越出规定目录的攻击手法 |
| **白名单校验（whitelist）** | 只允许"明确允许"的值通过（比黑名单安全） |
| **大小写不敏感比较** | Windows 路径不区分大小写，安全判断必须 `toLowerCase` 后再比 |
| **normalize（规范化）** | 把路径里的杂分隔符/`.`/`..` 整理成标准写法 |
| **占位符（placeholder）** | 配置里的"替身"，运行时替换成真值（`{{workspace}}` → 工作区绝对路径） |
| **单一事实源** | 全项目文件操作都从 `getWorkspacePath()` 拿根，改一处全链路跟着变 |
| **配置即授权** | MCP 配置哲学：给一个 json = 给一种能力，删掉 = 收回 |
