## 🎯 本课练习目标

- 能说出记忆写入的"防膨胀三连"
- 能解释为什么不上向量库
- 能区分记忆表与 AGENTS.md 的分工
- 能解释检索综合分"覆盖率 × 0.7 + 热度 × 0.3"的设计意图

## ✍️ 练习

### 练习 1：读代码——相似度（入门）

**目标**：理解"短侧覆盖率"比经典 Jaccard 好在哪。

**步骤**：

1. 读 `bigrams` 与 `similarity`（约 L48-66）。
2. 手工算：`similarity("用户喜欢简洁的回答", "用户喜欢简洁的回答，也接受表格")` 大概是多少？（用"短侧覆盖率"口径）
3. 再想：为什么用 bigram 而不是单字或整句？

**预期结果（自检）**：能算出接近 1 的相似度（旧内容被新内容完全覆盖），并说出"bigram 适合中文双字词、比单字准、比整句省"。

**提示**："短侧覆盖率" = 交集 ÷ 较小那侧的片段数；旧条是短侧。

---

### 练习 2：动手——去重合并（进阶）

**目标**：亲眼看到 `merged` 生效。

**步骤**：

1. 让 agent 记住"用户喜欢表格化输出"（或用记忆管理页手动加）。
2. 换个说法再让它"更新"同一条：如"用户喜欢表格化的回答，别用大段文字"。
3. 去记忆管理页看：是新增了一条，还是更新了原来那条（细节里应有"已更新"字样）？

**预期结果（自检）**：第二条没有新增，而是合并更新了第一条（`merged=true`），记忆总数没涨。

**提示**：相似度 ≥ `MEMORY_MERGE_THRESHOLD`（0.6）就合并；想想"完全相反"的两条会不会合并。

---

### 练习 3：LRU 淘汰（进阶）

**目标**：验证"满了删最久没用过的"。

**步骤**：

1. 读 `addMemory` 里容量上限的代码（`ORDER BY last_used_at ASC` 那段）。
2. 临时把 `MEMORY_LIMIT` 改成 3（或脚本连加超过上限的记忆），观察最久没被用的那条被淘汰。
3. 改回 100。

**预期结果（自检）**：加第 4 条时，`last_used_at` 最早的被删；若某条刚被 touch 过则不会被先删。

**提示**：`touchMemories` 会刷新 `last_used_at`——被用过的记忆"续命"。

---

### 练习 4：AGENTS.md 项目记忆（挑战）

**目标**：理解"文件级约定"与"记忆表"的分工。

**步骤**：

1. 在工作区根写一个 `AGENTS.md`，约定一句话，如"所有回复以『（按项目约定）』开头"。
2. 随便聊一句，看 agent 是否遵守。
3. 追问：这条约定如果写在"记忆表"里 vs 写在 `AGENTS.md` 里，本质区别是什么？（谁写的、谁维护、入库吗）

**预期结果（自检）**：agent 遵守 AGENTS.md；你能说出"AGENTS.md 是人和团队写的项目宪法（入库、可控），记忆表是模型自己攒的个性化事实（随用随攒）"。

**提示**：`AGENTS.local.md` 是私有版（`.gitignore` 排除，不入库）；对照 `loadProjectMemory` 读的两个文件。

---

### 练习 5：读代码——检索综合分（进阶）

**目标**：理解"覆盖率 + 热度"怎么解决"长记忆命中一词虚高"与"时效"两个问题。

**步骤**：

1. 读 `searchMemories`（约 L207-280）里的打分逻辑与 `recencyFactor`。
2. 构造两个反例说明"只数命中次数"的缺陷：① 长记忆命中一个词 vs 短记忆命中一个词；② 一条记忆昨天刚被用过 vs 一条半年前用过（内容同样相关）。
3. 回答：为什么 `recencyFactor` 用 `last_used_at` 而不是 `created_at`？

**预期结果（自检）**：能说出——覆盖率 = 命中片段覆盖内容的比例（短小精悍的更容易浮上来）；热度 = 90 天线性衰减（最近常用的优先）；`last_used_at` 会被 `touchMemories` 在每次注入时刷新，所以它代表"最近是否仍在使用"，而 `created_at` 只是"什么时候写的"（一条半年前写的、但每周都在用的记忆热度应该高）。

**提示**：打分是"先词面过滤（hits>0）再算分"——热度只是让"已相关"的记忆排序，不会把无关记忆带进 prompt。

---

### 练习 6：动手——热度排序 + 补齐（进阶）

**目标**：亲眼看到"热度"影响注入与管理页排序。

**步骤**：

1. 记两条关键词相同的记忆（如"用户喜欢简洁回答"、"用户喜欢表格输出"），再手动加一条很久不用的（可临时把其 `last_used_at` 改成很久以前——用 SQL 或脚本）。
2. 多跟 agent 聊几次"简洁"相关的问题（触发注入 + touch 保活）。
3. 去记忆管理页看排序与"上次使用"；再读 `agentLoop` 的 `memoryBlock`，确认"命中不足 3 条时用 `recentMemories` 补齐"。

**预期结果（自检）**：常被用的那条排到前面、显示较新的"上次使用"；`memoryBlock` 里补齐来源是"最近使用"（`recentMemories`）而不是"最近创建"。

**提示**：`recentMemories` 按 `last_used_at DESC` 排序；想一想"无共同词提问（如『我有什么偏好』）"时，补"用户常提的"是不是比补"刚写的"更合理。
