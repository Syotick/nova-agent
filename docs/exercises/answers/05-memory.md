# 答案 05：记忆系统

> 对应 [练习册](../05-memory.md)。**做完题再看本页**。

---

## 练习 1：相似度

**答案**：两条内容前者是后者的子串（旧条被新条完全覆盖）。短侧覆盖率 = 交集 ÷ 短侧 bigram 数 ≈ 1（新条除了包含旧条全部 bigram 还多几个，交集等于短侧全集）。经典 Jaccard（交集÷并集）则会因为新条更长而掉到 0.5 上下，可能不达 0.6 阈值。

bigram 理由：中文双字词多（"回答""简洁"），相邻两字做特征比单字准、比整句省；短侧覆盖率回答的是"A 是不是 B 的补充/改写"——这正是"同一事实的更新"最常见的形态。

**为什么**：对应指南 05 的 §4——"注释写为什么，不写是什么"的示范。

---

## 练习 2：去重合并

**答案**：第二条与第一条相似度 ≥ 0.6，走 UPDATE 更新原条，merged=true，记忆总数不涨。若两条"完全相反"（如"喜欢简洁" vs "喜欢详细"），公共 bigram 少，相似度低于阈值 → 不合并，存成两条。

**为什么**：防"同一个事实被不同表述存了 N 条"——这是"防膨胀三连"里的第二连。对应指南 05 的 §5。

---

## 练习 3：LRU 淘汰

**答案**：MEMORY_LIMIT 改小（如 3）后，加第 4 条时 ORDER BY last_used_at ASC 命中最久没被用的那条并删除。刚被 touchMemories 刷新过 last_used_at 的记忆不会被先删。

**为什么**：高频记忆保得住、低频记忆让位——防止总量无限膨胀，对应指南 05 的 §5 第三连。

---

## 练习 4：AGENTS.md

**答案**：在工作区根写 AGENTS.md 约定后，agent 每轮都读到并遵守。区别：

| | 记忆表（memories） | AGENTS.md |
|---|---|---|
| 谁写 | 模型自己（remember 工具） | 人和团队 |
| 内容 | 个性化偏好/事实 | 项目约定/架构/命令 |
| 维护 | 自动去重+LRU | git 管理（AGENTS.local.md 私有） |
| 生命周期 | 容量上限淘汰 | 随文件存在 |

**为什么**：记忆表是"模型攒的便签"，AGENTS.md 是"项目的宪法"——分工清晰，对应指南 05 的 §6.5。

---

## 练习 5：检索综合分

**答案**：
- 只数命中次数的缺陷：① 一条 200 字记忆命中"简洁"一次，和一条 10 字记忆命中一次，都被算成"命中 1"——覆盖率（命中片段长度 ÷ 记忆内容长度）解决了这个"不公平"，短小精悍的记忆更容易浮上来；② 同样相关的记忆，一条昨天用过、一条半年前用过，只数命中就分不出先后——`recencyFactor`（90 天线性衰减）让最近常用的排前。
- 为什么用 `last_used_at` 而非 `created_at`：`last_used_at` 每次注入被 `touchMemories` 刷新，代表"最近是否仍在使用"；`created_at` 只是"什么时候写的"。一条半年前写但每周都在被引用的记忆，热度应该高——这只有 `last_used_at` 能表达。

**为什么**：打分是"先词面过滤（hits>0）再算分"——热度只影响"已相关"记忆的排序，绝不把无关记忆带进 prompt（防噪声）。综合分 = 覆盖率×0.7 + 热度×0.3，相关为主、热度为辅。对应指南 05 的 §6。

---

## 练习 6：热度排序 + 补齐

**答案**：常被用的那条因每次注入被 touch 刷新 `last_used_at`，在记忆管理页排到前面、显示较新的"上次使用"；`agentLoop` 的 `memoryBlock` 在"命中不足 3 条"时用 `recentMemories`（按 `last_used_at DESC`）补齐。

**为什么**："无共同词提问（如『我有什么偏好』）"时，词面检索失效，只能靠热度兜底——该补的是"用户常提的"（最近使用的），而不是"刚写的"（可能是一条从没被用过的旧偏好）。热度让"保活机制"从后台数据变成用户可见的排序。对应指南 05 的 §6。

---

## 练习 7：一键可插拔 + 解耦

**答案**：取消"记忆"勾选后，三处一起关——remember 工具不再注册（模型无法写入）、`memoryEnabled` 为 false 使 `memoryBlock=''`（不再检索注入）、记忆指令段不拼入 system（不再提示"用 remember"）。"我有什么偏好"答不出、也记不进新东西。主循环只依赖 `shouldRegisterBuiltin(...)` 这一个布尔开关；检索/拼块/保活全在 `memory.ts` 的 `buildMemoryBlock` 里，拔掉记忆时主循环零改动。勾选回来即恢复。

**为什么**：这就是"机制可插拔、改动解耦"——记忆是 agent 循环的**可选模块**而非焊死的部分。`shouldRegisterBuiltin` 语义（未配置/空数组 = 全开）保证旧数据默认启用，向后兼容。对应指南 05 的 §6"可插拔"小节。
