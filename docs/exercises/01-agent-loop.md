# 练习册 01：Agent Loop

## 🎯 本课练习目标

- 能说清一个 turn 的 7 个阶段及其顺序理由
- 能区分 `streamText` 的职责与你的外围职责
- 能解释中断清理（发散式清理）为什么是三件事

---

## ✍️ 练习

### 练习 1：找 7 个阶段（入门）

**目标**：对着真实代码说出"一个 turn 的 7 个阶段"各自在哪。

**步骤**：

1. 打开 `server/agentLoop.ts`，定位 `runTurn` 函数。
2. 从函数开头到 `return finalMsg`，把代码按"阶段"切段，标出每段的起止行号。
3. 为每段写一句话：这一阶段在干嘛、为什么必须在现在这个位置。

**预期结果（自检）**：你能画出下面这张"阶段流水线"并标出每段的行号区间：

```
① 压缩检查 → ② 用户消息落盘+附件 → ③ 装配工具 → ④ 拼 system prompt
→ ⑤ streamText 多步执行 → ⑥ 收集结果 → ⑦ 落盘+done
```

**提示**：`streamText` 那一步在代码里是 `const result = await streamText({...})` 到 `await result.steps`，注意它和"装配工具""拼 prompt"是两回事。

---

### 练习 2：预测行为——去掉 `stopWhen`（入门）

**目标**：理解 `MAX_STEPS` 步骤上限是"预算先行的防御"。

**步骤**：

1. 找到 `stopWhen: isStepCount(MAX_STEPS)` 这一行。
2. 先别改代码，回答：如果把这一行删掉，一个需要"反复搜索→看结果"的任务会怎样？
3. 再实际改掉它（临时），跑一个会让 agent 反复用 `web_search` 的任务，观察行为，然后改回来。

**预期结果（自检）**：你的预测和实际观察一致：删除后 agent 会一直循环下去，token 和时间没有上限。

**提示**：想想"没有预算"的循环对成本意味着什么；`web_search` 是适合用来触发反复循环的工具。

---

### 练习 3：动手改——prompt 即策略（进阶）

**目标**：体会 system prompt 里的"执行约束"如何决定 agent 行为。

**步骤**：

1. 在 `stepBudget` 那段模板字符串里，加一句你自己的规则，例如："每次使用 run_command 前，必须先用 read_file 确认文件存在。"
2. 重启后端，让 agent 做一个需要"改文件+验证"的任务。
3. 观察它是否遵守你新加的规则；不遵守的话，想想是规则写得不够清楚还是被别的约束覆盖。

**预期结果（自检）**：agent 的行为明显受你新增的那句话影响（往你要求的方向偏移）。

**提示**：提示词是"软约束"——它不保证 100% 遵守，但能显著改变倾向。这正是 prompt 工程的现实。

---

### 练习 4：中断清理为什么是"发散式"（挑战）

**目标**：理解 `abortRun` 的三件事缺一不可。

**步骤**：

1. 读 `abortRun`（约 L29-40）和 `killSessionProcesses`、`activeSubruns` 的用法。
2. 构造一个场景：agent 先派了一个 subagent（子任务在跑），然后主线程又跑了一个 `npm run dev` 之类的长命令，此时用户点停止。
3. 追踪代码，回答：如果不做第 2、3 件事（只 abort 流），会发生什么？写出具体的后果。
4. 动手验证：让 agent 跑长命令，点停止，去任务管理器确认 node 进程被清干净。

**预期结果（自检）**：你能写出"只 abort 流"的两种遗留：① 命令进程树还在跑（占端口）；② 子任务还在烧 token。并验证实际清理生效。

**提示**：`activeSubruns` 是"主会话 → 子任务 abort 集合"，`killSessionProcesses` 是"会话 → 命令进程集合"——两个账本管两类资源。
