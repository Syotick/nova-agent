# 练习册 02：MCP 客户端

> 读完 [指南 02](../guide/02-mcp.md) + 代码 `server/mcp.ts` 后完成。规则：先自己动手，做完再对答案（答案在 [answers/02-mcp.md](answers/02-mcp.md)，别偷看）。

## 🎯 本课练习目标

- 能说清 MCP 的 server/client 模型与"为什么用子进程"
- 能背出并解释建立连接的四步
- 能手写一个极简 MCP server 并让 agent 用起来

---

## ✍️ 练习

### 练习 1：找"建立连接四步"（入门）

**目标**：对着真实代码说出 `establish` 的四步各自在干嘛。

**步骤**：

1. 打开 `server/mcp.ts`，定位 `establish` 函数。
2. 按顺序标出四步：建 client / 建 transport / connect 握手 / listTools。
3. 为每一步写一句"这一步解决什么问题"。

**预期结果（自检）**：你能默写出四步，并解释为什么第 3 步（握手）不成功后面就没法继续。

**提示**：transport 用 `StdioClientTransport`，它的 `command/args` 就是"要 spawn 哪个程序"。

---

### 练习 2：为什么是子进程（入门）

**目标**：说清"把工具做成独立进程"的三个理由。

**步骤**：

1. 阅读指南 02 的 §5（establish）。
2. 不查资料，用自己的话写出：把 MCP server 做成独立子进程（而不是把工具代码塞进我们进程）的 3 个好处。
3. 再想一个反例：什么情况下"塞进同一进程"会更方便？

**预期结果（自检）**：能写出"语言无关 / 隔离 / 即插即用"三个理由，并给出一个合理的反例思考（如：极小的纯本地工具塞进进程省掉 IPC 开销）。

**提示**：想想 server 崩溃会发生什么；再想想换一种语言的 server 还能不能用。

---

### 练习 3：写一个 10 行的 MCP server（进阶）

**目标**：亲手体会"协议"到底在说什么。

**步骤**：

1. 在项目根写 `my-tool-server.js`（用官方 SDK，约 10 行）：暴露一个 `add(a,b)` 工具。
2. 在 `mcp-servers/` 加一个 `demo.json` 配置指向它。
3. 保存后去「工具」页刷新：看到 `add` 工具出现。
4. 让 agent 用它算一道加法，确认真的能调。

**预期结果（自检）**：工具页出现 `add`；agent 能调用它并返回正确结果；全程**没有重启后端**。

**提示**：模板代码在指南 02 的 §11 动手建议里就有；`command` 用 `"node"`，`args` 用 `["./my-tool-server.js"]`。

---

### 练习 4：指数退避——读调度器（挑战）

**目标**：理解重连为什么"翻倍等待 + 封顶 + 上限"。

**步骤**：

1. 读 `scheduleReconnect`（约 L191-215）与 `RECONNECT_BASE_DELAY_MS / MAX_DELAY_MS / MAX_ATTEMPTS` 常量。
2. 写出：延迟序列长什么样？为什么封顶 120s？为什么超过 20 次就暂停？
3. 动手：把 `mcp-servers/playwright.json` 的 `command` 改成不存在的命令，保存，观察管理页状态和后端日志的重连节奏；再改回来。

**预期结果（自检）**：你能写出延迟序列（5s→10s→20s→40s→80s→120s→120s…），并解释"翻倍防重试风暴、封顶防无限等、暂停防永动机"。日志里能看到间隔越来越长的重连尝试。

**提示**：`2 ** retryCount` 是翻倍的实现；对照 `MAX_ATTEMPTS` 看"超过后"的代码分支。
