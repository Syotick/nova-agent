# 练习册 07：工作区 —— 文件权限边界

> 读完 [指南 07](../guide/07-workspace.md) + 代码 `server/workspace.ts` 后完成。规则：先自己动手，做完再对答案（答案在 [answers/07-workspace.md](answers/07-workspace.md)，别偷看）。

## 🎯 本课练习目标

- 能说出三类被拒绝的"危险目标"及理由
- 能解释为什么安全判断必须忽略大小写
- 能说清 `{{workspace}}` 占位符的联动价值

---

## ✍️ 练习

### 练习 1：读代码——危险目标（入门）

**目标**：背出工作区校验拒绝哪三类输入。

**步骤**：

1. 读 `validateWorkspaceRaw`（约 L62-83）。
2. 列出被拒绝的三类情况，并为每一类写一句"为什么拒绝"。
3. 追问：`validateWorkspaceRaw` 是纯函数（不碰数据库），好处是什么？

**预期结果（自检）**：能说出——① 项目根（agent 会拿到源码/数据库）；② 密钥文件目录或其祖先（filesystem 能读到 API key）；③ 脏输入（NUL/超长）。纯函数的好处：测试直接喂字符串断言，不起服务（`workspace.test.ts` 就是这么测的）。

**提示**：密钥存在项目**上级**的 `.nova-agent-key.json`，所以工作区不能指向"上级目录及其更上层"。

---

### 练习 2：读代码——大小写不敏感（进阶）

**目标**：理解为什么必须 `toLowerCase` 比较。

**步骤**：

1. 读 `samePath`（约 L16-19）。
2. 构造一个攻击：Windows 下如何用"大小写变体"绕过"拒绝项目根"的判断？（推理，不要真配）
3. 说出为什么 `D:\\a` 与 `d:\\A` 是同一个目录。

**预期结果（自检）**：能说出"项目根为 `D:\\proj\\nova-agent` 时，填 `d:\\PROJ\\Nova-Agent` 若不忽略大小写就能绕过；toLowerCase 后二者相等 → 被拒"。

**提示**：Windows 路径不区分大小写；字符串比较区分——这就是"看起来对、实际可绕过"的典型细节。

---

### 练习 3：动手——切工作区（进阶）

**目标**：亲眼看到工作区边界生效。

**步骤**：

1. 输入框工具栏点工作区，填 `my-test`（相对路径），保存。
2. 在 `my-test/` 放一个文件，问 agent"列出我的文件"。
3. 追问：再问它"看看项目根目录有没有 package.json"，它应该看不到（filesystem 挂载根 = 工作区）。

**预期结果（自检）**：agent 只看到 `my-test/` 里的内容，看不到项目根/工作区外的文件。

**提示**：filesystem MCP 的挂载根就是工作区（`{{workspace}}` 占位符替换成的路径）。

---

### 练习 4：被拒绝的目标（挑战）

**目标**：验证"危险目标"确实被拒。

**步骤**：

1. 工作区入口填 `..`（项目上级），保存——预期 400 拒绝。
2. 填项目根路径（`pwd` 的绝对路径），保存——预期 400 拒绝。
3. 填一个普通新目录（如 `my-app`），保存成功，再改回默认（清空）。

**预期结果（自检）**：`..` 和项目根被拒（错误信息说明原因）；正常目录能保存。整个流程不需要重启。

**提示**：校验在 `setWorkspacePath` 里"先校验后存储"——不通过直接返回错误信息，不会把脏值写进配置。
